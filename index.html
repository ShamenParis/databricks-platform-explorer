Cloud Deployment Architecture

Databricks operates across three decoupled planes: the Control Plane (managed by Databricks), the Compute Plane (your cloud account VPC or Databricks serverless), and Cloud Storage.

Control Plane

Managed by Databricks in the Databricks AWS account. Houses the web app, cluster manager, job scheduler, and metadata services.

Account Console
Workspace Web App
Cluster Manager
Job Scheduler
REST API Gateway
Metadata Store
Unity Catalog Service
Model Serving
Encrypted Secure Channel (TLS / Private Link)

Compute Plane

Where your data is processed. Classic: EC2 in your AWS account (VPC). Serverless: Managed by Databricks in a secure Databricks account.

Classic Compute (your AWS account)
All-Purpose Clusters (EC2)
Job Clusters (EC2)
SQL Warehouses (Classic)
Apache Spark + Photon
Customer VPC / Subnet
Serverless Compute (Databricks account)
Serverless SQL Warehouses
Serverless Jobs
Serverless Notebooks
Per-workspace isolation
S3 API / IAM Role Credential Vending

Storage Layer

Data stored in cloud object storage in your account. Delta Lake tables, Unity Catalog Volumes, and workspace system data all reside here.

Amazon S3 (your account)
Delta Lake Tables
Unity Catalog Volumes
Workspace Storage Bucket
DBFS (Legacy)

Databricks Object Hierarchy

Account

Top-level construct. Manages identity, billing, workspaces, and Unity Catalog metastores across your organisation.

Workspace

Collaboration environment per region. Users run compute, notebooks, jobs, and SQL queries within a workspace.

Unity Catalog Metastore

Central governance system for data assets. Namespace: catalog.schema.object. Can be attached to multiple workspaces.
